## [id=s2] 1. 처리 흐름 (관리자 쪽 그래프)데모에 필요 M-1・M-3
### 1-0. 그래프 앞: 관리자 계정(등록・교대・로그인) 2장으로 대체데모에 필요 M-4
11/04 결정을 반영했다. 이 흐름은 그래프 밖에서 일어나며, 그래프의 상태와 노드는 바뀌지 않는다. 관리자는 1점포에 활성 1명이다.
운영 스크립트: 점포 + 최초 관리자 등록→로그인(이메일・비밀번호 → JWT)→[교대 시] 현 관리자가 초대 코드 발급→새 사람이 코드+이메일+비밀번호로 등록→이전 계정은 무효(삭제하지 않음)→그래프 시작 이후는 1-1
 | 단계 | 누가 | 하는 일 | DB
 | A. 최초 1명 | 운영(스크립트) | 관리자가 아직 없으므로 점포와 관리자를 한꺼번에 등록한다 | stores manager_accounts
 | B-1 | 현 관리자 | 로그인한 상태에서 「초대 코드 발급」을 누른다. 이 발급이 이전 관리자의 본인 확인을 겸한다 | —
 | B-2 | 시스템 | 점포에 묶인 1회용 코드를 만든다(유효기간 1일). DB에는 해시만 저장한다 | invite_codes
 | B-3 | 현 관리자 | 새 사람에게 코드를 전한다(화면에 표시하는 안) | —
 | B-4 | 새 사람 | 등록 화면에서 코드+이메일+비밀번호를 입력한다 | —
 | B-5 | 시스템 | 코드가 유효한지 확인한다(존재・기한 내・미사용・점포 일치) | invite_codes
 | B-6 | 시스템 | 한 트랜잭션으로 이전 활성 계정을 무효 → 새 계정을 점포에 연결 → 코드를 사용 완료로 한다 | manager_accounts invite_codes
 | C. 로그인 | 관리자 | 이메일・비밀번호로 인증하고 JWT를 발급한다 | manager_accounts
 | D. 승인계 조작 | 관리자 | 승인 / 재편성 요청 / 편집 저장은 토큰을 확인한 뒤 접수한다 | shift_approvals
 | E. 개발 중 | 개발자 | 로그인을 건너뛰는 설정을 따로 둔다. 시연의 메인 흐름에는 넣지 않는다 | —
- 그래프와의 접점: 「지금 시작」・승인・재편성 요청・편집 저장은 JWT 확인 후에만 접수한다. 승인 노드(manager_review)는 JWT의 관리자 ID를 shift_approvals.approved_by에 남기므로, 교대 후에도 누가 승인했는지 알 수 있다.
- 1점포 1명의 지키는 방법: 이전 계정을 지우지 않고 무효로 하므로, 「활성인 관리자는 점포당 1명」으로 DB에서 막는다(부분 유일 인덱스). 마지막 1명을 무효로 만드는 조작은 허용하지 않는다(제안).
- 무효 계정의 JWT(제안): 로그아웃이 서버 쪽 토큰 폐기를 하지 않으므로, 요청마다 is_active를 확인한다(또는 JWT 기한을 짧게).
- 실패 시 응답(제안): 코드가 없음・기한 지남・사용 완료・점포 불일치는 같은 응답으로 돌려, 어느 경우인지 알 수 없게 한다.
- 미결: 이전 관리자가 움직일 수 없을 때(운영이 발급하는 안), 무차별 대입 공격 대책(횟수 제한), 비밀번호 재설정, 코드를 전하는 방법(화면 표시만/알림도). 8장 참조.
### 1-1. 편성 그래프데모에 필요 M-1
10/16 업무 흐름 그림을 기준으로, 11/3의 확정을 반영했다. 직원은 그래프 밖에서 LINE으로 입력하고 확정 시프트를 받는다.
시작: 마감 시각 또는 「지금 시작」→직원 정보 수집(MCP로 DB 읽기)→스킬 확인 (미확인 시 대기/진행 미정)→초안 작성(LLM, 점장 지침 우선)→검증(코드)→관리자 확인・승인→확정 저장・LINE 통지(1회)
- 검증에서 문제가 나오면 초안 작성으로 돌아간다(회수 상한은 미정, D-e 후보: 재편성 3회 + 반려 2회 후 점장의 직접 수정).
- 인원이 부족하면 코드가 LINE으로 후보에게 질문한다([가능][불가]). 응답 대기 동안 그래프는 멈추고 체크포인트에 저장된다.
- 확정 후 결원은 범위 밖. 점장이 전화로 처리하고, 결과는 확정표 수정 화면에 반영하며 저장 시 검증이 돈다(잠정, D-b).
- 그림의 「수동 편성(Excel)」은 필요 여부부터 열려 있어 이번 범위에서 뺀다.

LangGraph는 대기 중에는 돌지 않고 체크포인트(PostgreSQL)에 상태만 남긴다. 재개는 그래프 밖의 런타임(워커)이 같은 thread에서 Command(resume=…)로 부른다(교수 3-3). 그래프의 개수는 메인+상담의 2개로 시작한다.
### [id=s1-3] 1-3. State 안(A3, 11/12 초안・팀 확인 전)데모에 필요 M-1
MVP의 State는 1-3이 우선이다. 위 1-2는 10/16 초안이며 스킬 관련 항목은 MVP 밖이다. 여기는 「무엇을 가지는가」만 적는다(그래프 본체는 손으로 쓰는 과제, 10/20 교수). 상태: 초안, 아즈키 확인 대기. 근거: 시제품 prototype_01.py의 State, 기준 문서(11/07・11/08 반영), MVP 할 일(A3・B・C).
#### 정해진 것
- 편성안은 검사가 통과한 뒤에 DB에 저장한다(아즈키 11/09). 검사 중인 안은 State의 draft_store_shift에만 있다.
- 자동 재편성 상한은 3회 그대로(기준 문서대로, 후보값・C6 측정으로 확인). 11/12에 한 번 「2회」로 썼다가, 점장의 재편성 요청(2회)과 헷갈린 것이라 취소했다.
- 「남는 인원(余り)」은 재편성의 계기(위반)로 한다(아즈키 11/12). 余り = 실제 인원 − 희망 인원(want). MVP는 희망 인원만 기준으로 한다(다른 날의 평균・바쁨은 다음 단계).
#### State 항목
 | 항목 | 형 | 시제품과의 차이 | 누가 쓰나・메모
 | store_id | int | 같음 | 입구 API
 | period_id | int | 추가 | 입구 API. 1기간 = 1 thread. DB를 읽는 열쇠

시제품에서 뺀다: deficiency(미사용), upper_limit(상수로 충분, 추측입니다), skill_check 관련(B7에서 삭제 예정).
#### 주의・미결
- decision은 시제품의 bool로는 3가지 조작(승인／재편성 요청+지시／편집 저장)을 표현할 수 없다.
- result의 problem_O는 의미를 읽을 수 없다. 이름을 다시 붙이길 권한다. draft_empty는 기준 문서의 「초안 0개의 행선지가 없다」 문제에 대응.
- 상한을 넘어 위반을 안은 채 승인 화면으로 가는 안은, DB에 저장하는 시점(승인／확정)에 처음 위반이 기록된다(추측입니다). validation_violations를 언제 쓸지는 미결.
- State의 모양을 나중에 바꾸면 대기 중인 재개가 깨질 수 있다(기준 문서의 기술. 미검증).
- 검사의 「중복 배치」는 시제품의 validate에 아직 없다(기준 문서도 「넣는다」).
- 「余り」도 위반으로 하면, 필수 위반(사원 부재・자격자 부족 등)을 고치는 횟수를 잡아먹을 우려가 있다. 미결: 余り 몇 명부터 위반으로 하나(문턱값) ／ 필수 위반이 남는 동안은 余り를 무시하나 ／ 余り를 돌릴 후보가 있을 때만 위반으로 하나(모두 제안・추측입니다).
- 「余り」를 위반에 더하는 것은 기준 문서의 검사 규칙 표(현재는 최소 인원 경고뿐)에 아직 반영되지 않았다. 기준 문서의 규칙(먼저 기준 문서를 고친다 → 3명에게 알린다 → 코드)에 따라야 한다.
확인 방법: 시제품의 State와 대조(prototype_01.py 103~112행). 추가 항목이 기준 문서에 근거가 있는지: extra_rules(DB 절), 두 카운터(상한 절), decision 3값(approve 절).

### 2-4. DDL (MVP 15 테이블, v17, 실행 확인 완료 — MVP의 유일한 정의)데모에 필요 M-1・M-4・M-8

-- CoverShift MVP schema v17 (2026-11-12) 基準文書(11/08版)を反映＋希望テーブル＋closing_ok＋半休(half_leave)  / 기준 문서(11/08판) 반영 + 희망 테이블 + closing_ok + 반휴(half_leave)
-- 1) 管理者アカウント
-- 1) 관리자 계정
-- [印] 데모에 필요 M-4  / デモに要る M-4
CREATE TABLE manager_accounts (
    manager_id     BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    email          TEXT NOT NULL UNIQUE,
    password_hash  TEXT NOT NULL,
    is_active      BOOLEAN NOT NULL DEFAULT true      -- 店長交代で古いアカウントは false にする（消さない）  / 점장이 바뀌면 옛 계정은 false로 한다(지우지 않는다)
);

-- 2) 점포(계정 1개 = 점포 1개)
-- [印] 데모에 필요 M-4  / デモに要る M-4
CREATE TABLE stores (
    store_id    BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    manager_id  BIGINT NOT NULL UNIQUE REFERENCES manager_accounts(manager_id),
    name        TEXT NOT NULL
);
-- 2-b) 招待コード（運営が発行 → 新しい管理者が登録に使う。1回だけ・1日有効。11/04 승혁 결정）
-- 2-b) 초대 코드(운영 측이 발급 → 새 관리자가 등록에 사용. 1회만・1일 유효. 11/04 승혁 결정)
-- [印] 데모에 필요 M-4  / デモに要る M-4
CREATE TABLE invite_codes (
    code        TEXT PRIMARY KEY,                                       -- ランダムな文字列（本番はハッシュ保存を推奨）  / 무작위 문자열(실서비스는 해시 저장 권장)
    store_id    BIGINT NOT NULL REFERENCES stores(store_id),            -- どの店舗の管理者を引き継ぐか  / 어느 점포의 관리자를 이어받는지

    used_by     BIGINT REFERENCES manager_accounts(manager_id),         -- 登録して新しく管理者になった人  / 등록해서 새로 관리자가 된 사람
    CHECK ((used_at IS NULL) = (used_by IS NULL))
);
-- 3) 曜日×時間帯ごとの初期設定（時間帯は1日3つ程度。1時間帯 = 1行）
-- 3) 요일×시간대별 초기 설정(시간대는 하루 3개 정도. 1시간대 = 1행)
--    開始・終了は「その曜日の一番早い開始 / 一番遅い終了」から読み取る。
--   시작・종료는 「그 요일의 가장 이른 시작 / 가장 늦은 종료」에서 읽는다.
--    資格者 = 登録販売者（MVPは登販のみ）。
--   자격자 = 등록판매자(MVP는 등판만).
CREATE EXTENSION IF NOT EXISTS btree_gist;
-- [印] 데모에 필요 M-1・M-8  / デモに要る M-1・M-8
CREATE TABLE store_time_rules (
    rule_id          BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    store_id         BIGINT   NOT NULL REFERENCES stores(store_id),
    weekday          SMALLINT NOT NULL CHECK (weekday BETWEEN 1 AND 7),   -- 1=月 ... 7=日  / 1=월 ... 7=일
    start_time       TIME     NOT NULL,
    end_time         TIME     NOT NULL,
    min_headcount    SMALLINT NOT NULL CHECK (min_headcount >= 1),        -- 休憩込みの必要人数  / 휴식 포함 필요 인원
    min_qualified    SMALLINT NOT NULL DEFAULT 0 CHECK (min_qualified >= 0),   -- 時間帯ごとの必要な資格者数（基準文書 11/07）  / 시간대별 필요한 자격자 수(기준 문서 11/07)
    CHECK (end_time > start_time),
    EXCLUDE USING gist (store_id WITH =, weekday WITH =,
        tsrange(('2000-01-01'::date + start_time), ('2000-01-01'::date + end_time)) WITH &&)
);
-- 4) 従業員登録
-- 4) 직원 등록
-- [印] 데모에 필요 M-1・M-7  / デモに要る M-1・M-7
CREATE TABLE employees (
    employee_id              BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    store_id                 BIGINT  NOT NULL REFERENCES stores(store_id),
    name                     TEXT    NOT NULL,
    is_regular               BOOLEAN NOT NULL,                      -- true=社員, false=アルバイト等  / true=정직원, false=알바 등
    has_qualification        BOOLEAN NOT NULL DEFAULT false,        -- 登録販売者かどうか  / 등록판매자인지
    closing_ok       BOOLEAN NOT NULL DEFAULT false,         -- 22:30の閉店まで残ってよい人か（検証ルール「22:30まではclosing_okの人だけ」。11/12 アズキ決定）  / 22:30 폐점까지 남아도 되는 사람인가(검증 규칙 「22:30까지는 closing_ok인 사람만」. 11/12 아즈키 결정)
    weekly_days              SMALLINT CHECK (weekly_days BETWEEN 1 AND 7),         -- 週に出る日数（曜日は問わない人向け。空欄=決まりなし）  / 주에 나오는 일수(요일은 상관없는 사람용. 빈칸=정해진 것 없음)
    fixed_weekdays           SMALLINT[] CHECK (fixed_weekdays <@ ARRAY[1,2,3,4,5,6,7]::SMALLINT[]),  -- 毎週出る曜日が固定の人向け（例 {1,3,5}=月水金。空欄=固定なし）  / 매주 나오는 요일이 고정인 사람용(예 {1,3,5}=월수금. 빈칸=고정 없음)
    line_user_id             TEXT UNIQUE,                           -- NULL = LINE未連携  / NULL = LINE 미연동
    link_token               TEXT UNIQUE,                           -- 初回LINE連携リンクの合言葉（連携したら消す）  / 첫 LINE 연동 링크의 암호(연동하면 지운다)
    link_token_expires_at    TIMESTAMPTZ,
    CHECK ((link_token IS NULL) = (link_token_expires_at IS NULL)),
    CHECK (fixed_weekdays IS NULL OR weekly_days IS NULL OR weekly_days = cardinality(fixed_weekdays))
);
-- 5) 毎月の設定（何月分か・提出期限・社員の公休日数）
-- 5) 월별 설정(몇 월분인지・제출 기한・정직원 공휴일수)
-- [印] 데모에 필요 M-1  / デモに要る M-1
CREATE TABLE shift_periods (
    period_id            BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    store_id             BIGINT      NOT NULL REFERENCES stores(store_id),
    target_month         DATE        NOT NULL CHECK (EXTRACT(DAY FROM target_month) = 1),  -- 2026-12-01 = 12月分  / 2026-12-01 = 12월분
    submission_deadline  TIMESTAMPTZ NOT NULL,                                              -- 希望の提出期限  / 희망 제출 기한
    designated_off_days  SMALLINT    NOT NULL CHECK (designated_off_days BETWEEN 0 AND 31), -- 社員1人あたりの月の公休日数  / 정직원 1명당 월 공휴일수
    off_request_limit    SMALLINT    CHECK (off_request_limit BETWEEN 0 AND 31),            -- 社員が出せる希望休の上限日数（空欄=制限なし）  / 정직원이 낼 수 있는 희망휴 상한 일수(빈칸=제한 없음)
    work_request_limit   SMALLINT    CHECK (work_request_limit BETWEEN 0 AND 31),           -- 社員が出せる希望出勤日の上限日数（空欄=制限なし）  / 정직원이 낼 수 있는 희망 출근일 상한 일수(빈칸=제한 없음)
    thread_id            TEXT        UNIQUE,                                                  -- 編成期間1つ=thread1つ（LangGraph/Aegra。11/07 승혁）  / 편성 기간 1개 = thread 1개(LangGraph/Aegra. 11/07 승혁)
    UNIQUE (store_id, target_month)
);
-- 6) 毎月の提出リンク（有効期限 = その月の提出期限。期限の列は持たない）
-- 6) 월별 제출 링크(유효 기한 = 그 달의 제출 기한. 기한 열은 두지 않는다)
-- [印] 데모에 필요 M-1  / デモに要る M-1
CREATE TABLE submission_links (
    token        TEXT   PRIMARY KEY,
    employee_id  BIGINT NOT NULL REFERENCES employees(employee_id),
    period_id    BIGINT NOT NULL REFERENCES shift_periods(period_id),
    UNIQUE (employee_id, period_id)      -- 1人に月1本。再発行は作り直し  / 1명에 월 1개. 재발급은 새로 만든다
);
-- 7) 従業員の希望（1人×1日で1行。休み = 時刻が空欄）
-- 7) 직원의 희망(1명×1일에 1행. 휴일 = 시각이 빈칸)
-- [印] 데모에 필요 M-1  / デモに要る M-1
CREATE TABLE availability_submissions (
    employee_id  BIGINT NOT NULL REFERENCES employees(employee_id),
    work_date    DATE   NOT NULL,
    kind         TEXT   NOT NULL CHECK (kind IN ('available','off','paid_leave','half_leave')),
        -- available  = 出られる（時間つき）。時間の範囲内で、AIが入れる時間を決めてよい。
        -- available  = 나올 수 있음(시간 포함). 시간 범위 안에서 AI가 넣을 시간을 정해도 된다.
        --              アルバイト/パートの「出勤可能時間」、社員の「出勤希望日」
        --             알바/파트의 「출근 가능 시간」, 정직원의 「출근 희망일」
        -- off        = 希望休（社員の希望休。上限は shift_periods.off_request_limit、アプリで数える）
        -- off        = 희망휴(정직원의 희망휴. 상한은 shift_periods.off_request_limit, 앱에서 센다)
        -- paid_leave = 有給の申請（全日。承認された案で、シフトには載るが出勤ではない）
        -- paid_leave = 유급 신청(전일. 승인된 안에서 시프트에는 실리지만 출근은 아니다)
        --              ※パート・アルバイトに許すかは未決
        --             ※파트・알바에게 허용할지는 미결
        -- half_leave = 半休（時刻つき。その時間どおりに出勤として案へ入れる＝範囲内で自由ではない）。
        -- half_leave = 반휴(시각 포함. 그 시간 그대로 출근으로 안에 넣는다 = 범위 안 자유가 아님).
        --              社員・パート・アルバイトとも出せる。希望休・出勤希望の上限には数えない。給与の扱いは未決
        --             정직원・파트・알바 모두 낼 수 있다. 희망휴・출근 희망 상한에는 세지 않는다. 급여 취급은 미결
        -- 行なし     = 社員:希望なし（配置してよい） / アルバイト・パート:出られない
        -- 행 없음    = 정직원: 희망 없음(배치해도 됨) / 알바・파트: 나올 수 없음
    start_time   TIME,
    end_time     TIME,
    PRIMARY KEY (employee_id, work_date),                          -- 1人1日1行。同じ日の再入力は上書き(UPSERT)  / 1명 1일 1행. 같은 날 재입력은 덮어쓰기(UPSERT)
    CHECK ((kind IN ('available','half_leave')) = (start_time IS NOT NULL AND end_time IS NOT NULL)),
    CHECK (start_time IS NULL OR end_time > start_time),
    CHECK (start_time IS NULL OR (EXTRACT(MINUTE FROM start_time) IN (0,30)
                              AND EXTRACT(MINUTE FROM end_time)   IN (0,30)))
);
-- 8) シフト案（AIが作る案・確定した案）。1か月分の案が何度か作られる
-- 8) 시프트 안(AI가 만드는 안・확정된 안). 한 달분의 안이 여러 번 만들어진다
-- [印] 데모에 필요 M-1・M-3  / デモに要る M-1・M-3
CREATE TABLE shift_drafts (
    draft_id    BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    period_id   BIGINT NOT NULL REFERENCES shift_periods(period_id),
    status      TEXT   NOT NULL DEFAULT 'draft' CHECK (status IN ('draft','confirmed')),
    parent_draft_id BIGINT REFERENCES shift_drafts(draft_id),             -- やり直しの元になった案（検証の指摘を受けて作り直した場合）  / 다시 만들기의 바탕이 된 안(검증 지적을 받아 다시 만든 경우)
    confirmed_at  TIMESTAMPTZ,                                            -- 管理者が承認した時刻  / 관리자가 승인한 시각
    confirmed_by  BIGINT REFERENCES manager_accounts(manager_id),         -- 承認した管理者（店長交代後も残る）  / 승인한 관리자(점장이 바뀐 뒤에도 남는다)
    CHECK ((status = 'confirmed') = (confirmed_at IS NOT NULL)),
    CHECK ((confirmed_at IS NULL) = (confirmed_by IS NULL)),
    CHECK (parent_draft_id IS NULL OR parent_draft_id <> draft_id)
);
-- 確定できる案は、1か月につき1つだけ
-- 확정할 수 있는 안은 한 달에 하나뿐
CREATE UNIQUE INDEX one_confirmed_draft_per_period ON shift_drafts(period_id) WHERE status = 'confirmed';
-- 9) 案の中身（誰が・いつ）。1人1日1行。
-- 9) 안의 내용(누가・언제). 1명 1일 1행.
--    kind='work' は出勤（時刻あり）、'paid_leave' は有給（シフトには載るが出勤ではない。時刻は空欄）
--   kind='work'는 출근(시각 있음), 'paid_leave'는 유급(시프트에는 실리지만 출근은 아님. 시각은 빈칸)
--    半休(half_leave)の日も kind='work' で時刻つきの出勤として入れる（出勤日数に1日と数える）。
--   반휴(half_leave) 날도 kind='work'로 시각이 있는 출근으로 넣는다(출근일수에 1일로 센다).
--    半休かどうかは availability_submissions で判定する（この表には印を持たない）
--   반휴인지는 availability_submissions로 판정한다(이 표에는 표시를 두지 않는다)
-- [印] 데모에 필요 M-1・M-3  / デモに要る M-1・M-3
CREATE TABLE shift_assignments (
    draft_id     BIGINT NOT NULL REFERENCES shift_drafts(draft_id),
    employee_id  BIGINT NOT NULL REFERENCES employees(employee_id),
    work_date    DATE   NOT NULL,
    kind         TEXT   NOT NULL DEFAULT 'work' CHECK (kind IN ('work','paid_leave')),
    start_time   TIME,
    end_time     TIME,
    break_start  TIME,          -- 休憩の開始（記録だけ。validateでは見ない）  / 휴식 시작(기록만. validate에서는 보지 않는다)
    break_end    TIME,
    PRIMARY KEY (draft_id, employee_id, work_date),
    CHECK ((kind = 'work') = (start_time IS NOT NULL AND end_time IS NOT NULL)),
    CHECK ((start_time IS NULL) = (end_time IS NULL)),
    CHECK (end_time > start_time),
    CHECK ((break_start IS NULL) = (break_end IS NULL)),
    CHECK (break_start IS NULL OR (kind = 'work' AND break_end > break_start AND break_start >= start_time AND break_end <= end_time)),
    CHECK (EXTRACT(MINUTE FROM start_time) IN (0,30) AND EXTRACT(MINUTE FROM end_time) IN (0,30))
);
-- 10) 業務の一覧（管理者が自由に設定。sort_order は「簡単な順」などの表示順）
-- 10) 업무 목록(관리자가 자유롭게 설정. sort_order는 「쉬운 순」 등의 표시 순서)
-- [印] 정해 두기만  / 決めておくだけ
CREATE TABLE tasks (
    task_id     BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    store_id    BIGINT   NOT NULL REFERENCES stores(store_id),
    name        TEXT     NOT NULL,
    sort_order  SMALLINT NOT NULL DEFAULT 0,
    UNIQUE (store_id, name)
);
-- 11) 誰がどの業務を一人でできるか【管理者が確認して確定した結果】（行がある = できる。行がない = 数えない）
-- 11) 누가 어느 업무를 혼자 할 수 있는가【관리자가 확인해서 확정한 결과】(행 있음 = 가능. 행 없음 = 세지 않음)
--     validateが信頼するのはこの表だけ。評価（自己・他己）は下の evaluations に溜めて、管理者が見て確定する
--    validate가 신뢰하는 것은 이 표뿐. 평가(자기・타인)는 아래 evaluations에 모아 두고 관리자가 보고 확정한다
-- [印] 나중(12/4 이후). 기준 문서에 없음, 요확인  / 後回し（12/4以降）。基準文書に無い、要確認
CREATE TABLE employee_skills (
    employee_id  BIGINT NOT NULL REFERENCES employees(employee_id),
    task_id      BIGINT NOT NULL REFERENCES tasks(task_id) ON DELETE CASCADE,
    PRIMARY KEY (employee_id, task_id)
);
-- 12) 時間帯ごとに、その業務をできる人が最低何人必要か
-- 12) 시간대별로 그 업무를 할 수 있는 사람이 최소 몇 명 필요한가
-- [印] 나중(12/4 이후). 기준 문서에 없음, 요확인  / 後回し（12/4以降）。基準文書に無い、要確認
CREATE TABLE store_task_needs (
    rule_id     BIGINT   NOT NULL REFERENCES store_time_rules(rule_id) ON DELETE CASCADE,
    task_id     BIGINT   NOT NULL REFERENCES tasks(task_id) ON DELETE CASCADE,
    min_people  SMALLINT NOT NULL CHECK (min_people >= 1),
    PRIMARY KEY (rule_id, task_id)
);
-- 13) 業務ごとの評価（自己評価と他己評価）
-- 13) 업무별 평가(자기 평가와 타인 평가)
--     自己評価: evaluator_id = employee_id（日付なし）
--    자기 평가: evaluator_id = employee_id(날짜 없음)
--     他己評価: 一緒に勤務した社員が付ける（work_date = 一緒に勤務した日）
--    타인 평가: 함께 근무한 정직원이 매긴다(work_date = 함께 근무한 날)
-- [印] 나중(12/4 이후). 기준 문서에 없음, 요확인  / 後回し（12/4以降）。基準文書に無い、要確認
CREATE TABLE evaluations (
    evaluation_id  BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    employee_id    BIGINT NOT NULL REFERENCES employees(employee_id),             -- 評価される人  / 평가받는 사람
    task_id        BIGINT NOT NULL REFERENCES tasks(task_id) ON DELETE CASCADE,
    evaluator_id   BIGINT NOT NULL REFERENCES employees(employee_id),             -- 評価する人  / 평가하는 사람
    rating         TEXT   NOT NULL CHECK (rating IN ('solo','guided')),           -- solo=一人でできる / guided=指導が必要  / solo=혼자 가능 / guided=지도 필요
    work_date      DATE,
    CHECK ((evaluator_id = employee_id) = (work_date IS NULL))
);
-- 自己評価は 人×業務 で1つ（書き直しは上書き）
-- 자기 평가는 사람×업무로 1개(다시 쓰면 덮어쓰기)
CREATE UNIQUE INDEX one_self_evaluation ON evaluations(employee_id, task_id) WHERE evaluator_id = employee_id;
-- 他己評価は 同じ評価者が、同じ日に、同じ人の同じ業務を2回つけられない
-- 타인 평가는 같은 평가자가 같은 날 같은 사람의 같은 업무를 2번 매길 수 없다
CREATE UNIQUE INDEX one_other_evaluation ON evaluations(employee_id, task_id, evaluator_id, work_date) WHERE evaluator_id <> employee_id;
-- 14) 検証で引っかかった内容（1件1行で溜める。次の作り直しにAIへ渡す「コメント」の元にもなる）
-- 14) 검증에서 걸린 내용(1건 1행으로 쌓는다. 다음 재작성 때 AI에 넘기는 「코멘트」의 바탕도 된다)
--     コメントの文章は保存せず、check_code と detail からコードで作る（同じ指摘は同じ文章になる）
--    코멘트 문장은 저장하지 않고 check_code와 detail에서 코드로 만든다(같은 지적은 같은 문장이 된다)
-- [印] 데모에 필요 M-1  / デモに要る M-1
CREATE TABLE validation_violations (
    violation_id  BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    draft_id      BIGINT NOT NULL REFERENCES shift_drafts(draft_id),   -- どの案で見つかったか  / 어느 안에서 발견됐는가
    check_code    TEXT   NOT NULL,                                      -- どのチェックか（6種類など）  / 어느 검사인가(6종류 등)
    work_date     DATE,                                                 -- 該当する日（なければ空欄）  / 해당하는 날(없으면 빈칸)
    employee_id   BIGINT REFERENCES employees(employee_id),             -- 該当する人（なければ空欄。名前は持たない）  / 해당하는 사람(없으면 빈칸. 이름은 갖지 않는다)
    detail        JSONB,                                                -- チェックごとの詳しい数字（例: {"need":2,"have":1,"time":"13:00"}）  / 검사별 상세 숫자(예: {"need":2,"have":1,"time":"13:00"})
    allowed_by    BIGINT REFERENCES manager_accounts(manager_id),       -- 例外として許可した管理者  / 예외로 허가한 관리자
    allowed_at    TIMESTAMPTZ,
    CHECK ((allowed_by IS NULL) = (allowed_at IS NULL))
);
CREATE INDEX ON validation_violations(draft_id);
CREATE INDEX ON validation_violations(check_code, work_date);
### 2-5. 미결・주의정해 두기만
- 데모에 필요 M-4 최초 점포와 첫 관리자・초대 코드는 운영자가 만든다(기준 문서 11/04). 정함.
- 정해 두기만 로그인 시도 횟수 제한, 비밀번호 재설정, 코드 전달 방법은 미정.
- 정해 두기만 운영 단계에서는 link_token・초대 코드・제출 토큰을 해시로 저장하길 권장한다(DB가 유출돼도 링크를 못 쓰게).
- 나중(12/4 이후) 링크에서 LINE userId를 얻는 방법은 확인하지 못했다. LIFF가 필요할 수 있다（추측입니다）.
- 나중(12/4 이후) 타인평가를 누가 입력하는지(관리자?)는 확인 필요（추측입니다: 관리자 입력）.
- 정해 두기만 확인 방법: 위 DDL을 PostgreSQL 16에 그대로 붙여 넣으면 오류 없이 실행된다. API는 아직 코드가 없어 FastAPI 구현 후 pytest로 확인한다.
- 정해 두기만 전일 유급(paid_leave)을 파트・알바에 허용할지 미결(11/12 아즈키). 반휴(half_leave)는 파트・알바도 가능.
- 정해 두기만 반휴의 급여 취급(유급인지)은 모름. 이번에는 정하지 않는다(11/12 아즈키, Q2).

### 2-6. 기준 문서(11/08판) 반영데모에 필요 M-1

#### ⑥ 실행 환경데모에 필요 M-1
- 시연은 Aegra + Postgres 위에서 돈다. 그래프는 Aegra에 올리고, 체크포인트는 Aegra가 Postgres에 저장(PostgresSaver 직접 사용은 뺌, D1). Aegra 버전은 고정.
- 입구 API 하나(D3): 관리자 Web・직원 답장 버튼의 요청을 받아 run(편성 시작)・resume(승인・재편성 요청・편집 저장・직원 답장)을 부른다.
- 잠금(D4): 편성 기간 하나 = thread 하나(→ shift_periods.thread_id). 같은 thread에 요청이 겹치면 하나만 처리하고 나머지는 「지금 편성을 처리하고 있습니다」.
- LINE: 스텁 함수가 보낼 내용을 로그・화면에 찍는다(D6). 무응답 2시간(D7): Aegra cron 또는 시연용 「시간 경과」 버튼 — 미정.
- 로그인: JWT 발급, 승인・재편성 요청・편집 저장은 토큰 확인. 개발 중에는 로그인을 건너뛰는 설정. 키・비밀번호는 코드에 쓰지 않고 .env(커밋 금지) + .env.example에 이름만.

## [id=s4] 4. DB 스키마 (V8 완전판 중 2장과 안 겹치는 24 테이블, 참고용)정해 두기만
V7의 DDL에 V8 변경을 적용한 전체다. PostgreSQL 16에서 처음부터 끝까지 실행해 오류 없이 34개 테이블이 만들어지는 것을 확인했고, 잘못된 값(한국어 구 코드, 이유 없는 확정 후 수정, 지시 없는 반려 등)이 거부되는 것도 확인했다. 실행 순서는 파일 순서 그대로다. btree_gist 확장이 필요하다. 변경점은 ** V8 ** 주석으로 표시했다.
### 4-1. 저장값 코드표정해 두기만
 | 항목 | V7 (한국어 값) | V8 (코드)
 | employees.employment_type | 정직원 / 파트타이머 / 아르바이트 | regular / part_timer / arbeit
 | employees.shift_end_mode | 계약시간까지 / 폐점까지 | until_contract_hours / until_closing
 | staff_skills.status | 미확인 / 지도필요 / 단독대응가능 | unconfirmed / needs_guidance / can_solo
 | shift_assignments.source | 희망반영 / agent제안 / 관리자수정 | wish_applied / llm_proposed / manager_edit
 | shift_drafts.created_by | agent / manager | llm / manager
 | shift_approvals.action | 승인 / 재조정요청 | approved / rejected (+ instruction)
 | contact_rounds.status | 진행중 / 확정 / 상한초과_관리자대기 / 취소 | in_progress / confirmed / limit_reached_waiting_manager / cancelled
 | contact_attempts.status | 대기 / 발송됨 / 가능 / 불가능 / 불확실 / 타임아웃 / 수동넘김 / 취소 | pending / sent / available / unavailable / uncertain / timed_out / manually_skipped / cancelled
 | onboarding_imports.status | 업로드됨 / 해석중 / AI제안완료 / AI실패_수동지정 / 점장확인완료 / 반영완료 / 폐기 | uploaded / interpreting / ai_proposed / ai_failed_manual / manager_confirmed / applied / discarded
 | period_off_rules.applies_to | 정직원만 / 전원 / 미확인 | regular_only / all / unconfirmed
### 4-2. 전체 DDL정해 두기만
-- ★ 다음 10개 테이블은 2장 2-4의 v15/v16이 유일한 정의라서 여기서는 뺐다:
--   stores, manager_accounts, invite_codes, employees, tasks, shift_periods,
--   availability_submissions, shift_drafts, shift_assignments, validation_violations
-- ★ 이 DDL은 V8 완전판의 나머지(참고용)다. 아래 FK는 빠진 테이블(UUID)을 가리키므로 단독으로는 실행되지 않는다.
-- Extension 설치 (시간대 중복 방지 제약용)
CREATE EXTENSION IF NOT EXISTS btree_gist;
-- -----------------------------------------------------
-- 1. 마스터 데이터 (Master Data)
-- -----------------------------------------------------
-- 자격증 마스터
-- [印] 나중(12/4 이후)
CREATE TABLE qualifications (
    qualification_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name              TEXT NOT NULL UNIQUE   -- 예: 약사면허
);
-- 시간대 마스터 (v6 개정: congestion_weight 삭제 및 DB 레벨 중복 방지 제약 반영)
-- [印] 나중(12/4 이후)
CREATE TABLE time_bands (
    band_id     UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name        TEXT NOT NULL,         -- 예: 개점~점심
    start_time  TIME NOT NULL,
    end_time    TIME NOT NULL,
    sort_order  INT NOT NULL,
    time_range  tsrange GENERATED ALWAYS AS (
        tsrange('2000-01-01'::date + start_time, '2000-01-01'::date + end_time)
    ) STORED,
    -- ** V5 신규 ** 길이 0 또는 역전된 시간대 방지 / 표시 순서 중복 방지
    CONSTRAINT band_start_before_end CHECK (end_time > start_time),
    CONSTRAINT band_sort_unique UNIQUE (sort_order)
);
ALTER TABLE time_bands
    ADD CONSTRAINT no_overlapping_bands EXCLUDE USING gist (time_range WITH &&);
-- -----------------------------------------------------
-- 2. 계정 / 인증 (매직링크 & 관리자 로그인)   ** V5.1 변경 **
-- -----------------------------------------------------
-- ** V5.1 ** V5의 accounts(LINE Login 겸용)와 invite_tokens는 삭제했다.
--   - 아르바이트의 PWA 접근: 매직링크 (magic_link_tokens. shift_periods를 참조하므로 아래 shift_periods 뒤에 정의)
--   - 관리자(Web) 로그인: manager_accounts (이메일/비밀번호)
-- LINE 연동 계정 매칭 테이블 (Webhook/수동 매칭용)
-- [印] 나중(12/4 이후)
CREATE TABLE line_contact_registry (
    line_user_id   TEXT PRIMARY KEY,          -- LINE Webhook userId
    first_seen_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    staff_id       UUID REFERENCES employees(staff_id),   -- NULL = 미매칭
    matched_by     UUID REFERENCES employees(staff_id),
    matched_at     TIMESTAMPTZ
);
-- -----------------------------------------------------
-- 3. 배치 기준 및 관리자 수동 설정
-- -----------------------------------------------------
-- 시간대별 업무 필요 인원
-- [印] 나중(12/4 이후)
CREATE TABLE staffing_requirements (
    id             UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    band_id        UUID NOT NULL REFERENCES time_bands(band_id),
    task_id        UUID NOT NULL REFERENCES tasks(task_id),
    required_count INT NOT NULL DEFAULT 1 CHECK (required_count >= 0),  -- ** V5: 음수 방지 **
    verified_by    UUID REFERENCES employees(staff_id),
    verified_date  TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE(band_id, task_id)
);
-- 핵심 판정 근거 (band × task 단독 대응 인원)
-- [印] 나중(12/4 이후)
CREATE TABLE required_solo (
    id             UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    band_id        UUID NOT NULL REFERENCES time_bands(band_id),
    task_id        UUID NOT NULL REFERENCES tasks(task_id),
    required_count INT NOT NULL DEFAULT 1 CHECK (required_count >= 0),  -- ** V5: 음수 방지 **
    verified_by    UUID REFERENCES employees(staff_id),
    verified_date  TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE(band_id, task_id)
);
-- 관리자 수동 혼잡도 승인 (v5/v6 개정: 계산식 폐지 후 수동 입력 전환)
-- [印] 나중(12/4 이후)
CREATE TABLE congestion_manual (
    id                 UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    date               DATE NOT NULL,
    band_id            UUID NOT NULL REFERENCES time_bands(band_id),
    task_id            UUID NOT NULL REFERENCES tasks(task_id),   -- ** V5 신규 **
    is_manual_override BOOLEAN NOT NULL DEFAULT TRUE,  -- 관리자 특일 승인 여부 (+1 필요 인원 적용)
    -- ** V5 확정: 승인 단위 = 날짜 × 시간대(band) × 업무(task).
    --    band는 평시 구조이고, 판촉이 어느 band의 어느 업무에 얹히는지가 판촉마다 다르기 때문.
    --    +1은 해당 (날짜, band, task)의 required_solo에만 적용된다.
    --    (requires_solo=false 업무에 대한 행은 의미가 없으므로 서비스 레이어에서 거부한다) **
    note               TEXT,
    verified_by        UUID REFERENCES employees(staff_id),
    created_at         TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE(date, band_id, task_id)
);
-- ** V5.1 신규 ** 매직링크 토큰 (아르바이트의 PWA 접근용)
-- shift_periods를 참조하므로 shift_periods 뒤에 둔다 (FK 순서).
-- expires_at : 발급 시 shift_periods.submission_deadline과 같은 값을 넣는다 (서비스 레이어 규칙. 마감 = 링크 실효)
-- used_at    : 최초 접근 시각 기록용(참고값). 유효기간 내에는 재사용할 수 있으므로 실효 판정에는 쓰지 않는다
-- 발급 조건(line_contact_registry 매칭이 끝난 직원만)은 서비스 레이어에서 강제한다
-- [印] 나중(12/4 이후)
CREATE TABLE magic_link_tokens (
    token       UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    staff_id    UUID NOT NULL REFERENCES employees(staff_id),
    purpose     TEXT NOT NULL,                 -- 예: 'shift_submission'
    period_id   UUID REFERENCES shift_periods(period_id),
    issued_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
    expires_at  TIMESTAMPTZ NOT NULL,
    used_at     TIMESTAMPTZ,
    CONSTRAINT magic_link_expiry_after_issue CHECK (expires_at > issued_at)
);
-- -----------------------------------------------------
-- 4. 스킬시트 & 희망 시프트
-- -----------------------------------------------------
-- 스킬시트 확정 판정값
-- [印] 나중(12/4 이후)
CREATE TABLE staff_skills (
    staff_id      UUID NOT NULL REFERENCES employees(staff_id),
    task_id       UUID NOT NULL REFERENCES tasks(task_id),
    status        TEXT NOT NULL CHECK (status IN ('unconfirmed', 'needs_guidance', 'can_solo')),
    verified_by   UUID REFERENCES employees(staff_id),
    verified_date TIMESTAMPTZ NOT NULL DEFAULT now(),
    PRIMARY KEY (staff_id, task_id)
);
-- -----------------------------------------------------
-- 4-2. ** V8 신규 ** 점장 지침 (D-h, D-i) / 스킬 불안 표시
-- -----------------------------------------------------
-- 본인의 「불안」 표시. 판정(staff_skills)과 별개이며 LLM・MCP에는 노출하지 않는다. 관리자 화면에 코드가 집계해 보여준다.
-- [印] 나중(12/4 이후)

## [id=s5] 5. 검증 코드・지침의 틀데모에 필요 M-1・M-2
### 5-1. 검증 위반 코드 (validation_violations.code, 11종)데모에 필요 M-1
 | 코드 | 의미 | 예외 허용(waive)
 | SKILL_SHORTAGE | 특정 업무의 단독 대응 인원 부족(can_solo만 센다. unconfirmed는 세지 않는다) | 가능
 | EXCLUSIVE_GROUP_SHORTAGE | 단독 업무끼리 겸무할 수 없어서 생기는 인원 부족 | 가능
 | QUAL_MISSING | 필수 자격 미보유 | 불가
 | HEADCOUNT_SHORTAGE / HEADCOUNT_EXCESS | 총원 부족 / 초과(초과는 참고 정보. 구조도 4-5) | 가능
 | NEWCOMER_RATIO | 신입 비율 초과(구조도에 없음. 취급 미결) | 미결
 | UNVERIFIED_SKILL | 스킬 미검증 인원이 배치됨(구조도에 없음. 취급 미결) | 미결
 | TRAINEE_UNSUPERVISED | needs_guidance 인원에게 같은 시간대의 can_solo 멘토가 없음 | 가능
 | DOUBLE_BOOKING | 같은 사람의 시간이 겹치는 배정 | 불가
 | OUTSIDE_AVAILABILITY | 제출한 희망 시간 밖의 배치(경고/위반 구분은 미결) | 가능(추측입니다)
 | RULE_VIOLATION 신규 | 점장 지침의 틀 규칙 위반. guideline_item_id로 규칙을 가리킨다. status=trial인 규칙은 경고만 | 가능
미제출 직원은 마감 시 「희망 없음(불가)」으로 취급한다(submission_notices.kind='deadline_treated_unavailable', 관리자에게 통지). 확정 후 수정에서는 물리(DOUBLE_BOOKING 등)・자격(QUAL_MISSING) 위반을 차단하고 그 밖은 reason을 남기고 허용한다.
#### V9 제안(11/12): 반휴와 「신청 시각」 검사데모에 필요 M-1
제안이다. 11종 목록에는 아직 넣지 않았고, 기준 문서에도 반영되지 않았다(기준 문서의 규칙: 먼저 기준 문서를 고친다 → 3명에게 알린다 → 코드).
 | 대상 | kind | 배치의 조건 | 지금의 검사 | 제안
 | 알바・파트 | available | 신청한 시간의 범위 안 | 시제품 check_requests가 검사한다(알바만) | 변경 없음. 코드는 OUTSIDE_AVAILABILITY
 | 정직원 | available(출근 희망일) | 신청한 시간의 범위 안(희망) | 검사 없음(check_requests가 사원을 보지 않는다) | 검사를 더한다. 필수/경고는 미결(추측입니다: 사원의 출근 희망은 보장이 아닌 희망이라 경고)
 | 전원(정직원・파트・알바) | half_leave | 신청한 시각 그대로(범위 안이 아니라 일치) | 검사 없음 | 검사를 더한다(필수・재편성, 추측입니다). 새 코드 HALF_LEAVE_MISMATCH를 제안
- OUTSIDE_AVAILABILITY와의 관계: available은 「범위의 밖」을 본다(≦). half_leave는 「일치」를 본다(＝). 「범위 안이지만 짧다・길다」는 OUTSIDE_AVAILABILITY로 잡히지 않는다. 같은 코드에 섞으면 의미가 흐려지므로 별도 코드를 제안한다(OUTSIDE_AVAILABILITY를 그대로 쓰는 안도 가능하며, 그 경우 종류를 context에 남긴다. 추측입니다).
- 예외 허용(waive): OUTSIDE_AVAILABILITY는 「가능(추측입니다)」. HALF_LEAVE_MISMATCH는 미결(추측입니다: 불가에 가깝다. 본인과 점포가 합의한 시각이고 급여와 얽힐 수 있다. 다만 반휴의 급여 취급은 모름).
- 반휴를 낸 날에 배치가 없는 경우의 취급은 미결(추측입니다: 반휴가 반영되지 않았으므로 위반).
### 5-2. 지침의 틀(template_key) 후보 — 초안데모에 필요 M-2
 | template_key | params 예(제안) | 점장의 말 예
 | max_consecutive | {"shift":"late","limit":1} | 늦은 근무를 2번 연속으로 넣지 마
 | max_hours | {"staff_id":…,"scope":"week","limit":20} | 이 사람은 주 20시간까지

후보 8개는 10/25 논의 기준이다. 10/16 데모의 이름(max_days_per_week, not_together)과 다르므로 정식 이름과 params는 확정이 필요하다. 이 표의 params와 예문은 이 문서의 제안이다.

## [id=s10] 10. 검증 방법데모에 필요 M-1

## [id=s0] 11. 개정 요약정해 두기만
### V9(11/12)의 변경
- MVP 장(2장) 신설: 인증 4종류, 설정・제출 CRUD, 15 테이블 DDL(v17). MVP의 DDL은 2장이 유일한 정의.
- 팀의 기준 문서(11/08판) 반영: 범위(M-1~M-8)・담당・검증 규칙・LLM 호출 약속・실행 환경(2-6). 초대 코드는 운영자 발급, 자격자는 인원수(min_qualified), thread_id 추가.
- 희망 테이블: kind(available / off / paid_leave / half_leave). 반휴는 그 시간 그대로 출근으로 배치, 상한에 세지 않음(11/12). employees.closing_ok 추가(11/12 아즈키 결정).
- 같은 이름의 이중 정의를 하나로: 4장에서 10개를 빼고 이름마다 한 번만(15+24=39). 4장은 V8만의 24개(참고용).
- 리더 요청(11/12): 모든 섹션・테이블・미결 사항에 「데모에 필요 M-n / 정해 두기만 / 나중(12/4 이후)」 인. 39 테이블 분류(3-0장). 맨 위에 「11/20 전에 읽는 곳과 담당」.
- 6장 API를 처리 흐름 순서의 Postman식 폴더(000~007)로, 각 API에 이름. 장 순서를 정리(1장 처리 흐름 → … → 11장 개정 요약 → 12장 확정 사항)하고 번호를 맞춤.
- min_headcount: 설정=경고 / 지시=보장 / 지시가 있는 칸은 지시의 숫자로 덮어쓴다(11/12 정함, 2-6 ⑦).
- State 안(A3)을 1-3장에 추가. 「余り」를 위반으로 하는 안(아즈키 11/12, 기준 문서 미반영).
- 참고: 표의 「V8」 열(유지/변경/신규)은 V7→V8의 변경 표시 그대로다. V9에서 바뀐 곳은 위 항목과 2장・3-0장에 있다.
- 편성 주체가 솔버에서 LLM으로 바뀐다(11/3 확정). 목적함수 5축・프리셋・T2 대화・CP-SAT 호출과 관련된 테이블과 API를 삭제한다.
- 검증(validate, 코드)이 유일한 보증이다. LLM의 출력은 그대로 채택하지 않고 반드시 코드 검증을 거친다. LLM이 정확히 편성하는지는 실측 전이라 효과를 단정하지 않는다.
- 스킬시트: 자기평가 초안 테이블을 삭제하고, 본인의 「불안」 표시(staff_skill_concerns)를 신설한다. 판정값은 관리자만 정한다.
- 점장의 지침을 저장하는 곳을 신설한다(D-h, D-i). 틀(템플릿)에 맞는 말은 규칙으로, 틀이 없으면 지침으로만 저장하고, 편성이 시작될 때의 지침 버전을 고정한다.
- DB 저장값을 영어 코드로 통일한다(10/1 결정). V7 본문은 아직 한국어 값이다.
- 관리자 계정을 초대 코드 방식으로 한다(11/04 결정). 1점포 1명, 코드는 1회용・유효 1일, 최초 1명은 운영 스크립트. stores와 invite_codes를 신설하고 manager_accounts를 점포에 연결한다.
- DB는 PostgreSQL 단일(10/20 우선). 체크포인트 저장소도 이에 따른다.
- 이번 발표용으로는 1개 경로에 필요한 부분을 직접 쓴다(희망 제출 → 초안 → 검증 → 승인 대기 → 확정). 연락 루프・휴일 관리・Excel 도입은 「다음 단계」다.
